# CaptureKit app

React Native UI (Expo SDK 58, New Architecture, strict TypeScript, expo-router) for CaptureKit. All capture logic is native Swift in the local Expo module [`modules/capture`](modules/capture):

```
modules/capture/
  index.ts                 TypeScript API: Capture (functions) + CameraPreview (view)
  ios/CaptureModule.swift  Expo bridge, no logic
  ios/*.swift              Shell: AVFoundation / CoreMotion glue
  ios/CaptureCore/         Pure Swift package with the logic, tested with `swift test`
```

**How CaptureCore gets into the app:** CaptureCore is a standalone Swift package for `swift test` on the Mac, but the app does not link it as a package. `ios/Capture.podspec` compiles its sources (`CaptureCore/Sources/CaptureCore/**/*.swift`) straight into the `Capture` pod, next to the shell files, so they form one Swift module. Shell code therefore uses CaptureCore types without `import CaptureCore`. `Package.swift` and `Tests/` are not part of the pod. A new CaptureCore source file is picked up by the next `pod install` (`npx expo prebuild` or `npx pod-install`); it must stay free of Expo, UIKit and AVFoundation imports.

The app is a **development build** (expo-dev-client), built locally with Xcode. Not Expo Go, not EAS. `ios/` is generated by `expo prebuild` (continuous native generation) and is not committed: configure native behaviour in `app.json`, never by editing `ios/`.

Screens: **Capture** (live back-camera preview, or an explanation: camera permission denied with an "Open Settings" button, camera failed to start with "Try again", or no camera), **Sessions** (empty for now), **Settings** (empty for now). The app is portrait only and asks for camera access only. Motion data (CMDeviceMotion) needs no permission, so there is no motion prompt; `NSMotionUsageDescription` is still in Info.plist. It never asks for the microphone.

## Checks

```sh
npm install
npx tsc --noEmit                                         # type check
npm test                                                 # TypeScript unit tests (jest-expo)
(cd modules/capture/ios/CaptureCore && swift test)       # CaptureCore tests
npx expo prebuild --platform ios                         # generates ios/ (once, or after config changes)
xcodebuild -workspace ios/CaptureKit.xcworkspace -scheme CaptureKit -configuration Debug \
  -sdk iphonesimulator -destination "generic/platform=iOS Simulator" CODE_SIGNING_ALLOWED=NO build
```

## Run on the iOS Simulator

```sh
npx expo run:ios
```

The Simulator has no camera, so the Capture screen shows "No camera available". That is expected.

## Run on an iPhone (manual check: live preview)

Requirements: a Mac with Xcode, an iPhone connected by cable (or paired for wireless debugging) with Developer Mode on (Settings > Privacy & Security > Developer Mode), and an Apple ID signed in to Xcode (Xcode > Settings > Accounts).

1. `cd app && npm install`
2. `npx expo prebuild --platform ios --clean` (regenerates `ios/` from `app.json`).
3. Signing, once: `open ios/CaptureKit.xcworkspace`, select the **CaptureKit** target > **Signing & Capabilities**, tick *Automatically manage signing* and pick your Team. If the bundle id `com.samsoncorbiere.capturekit` is taken for your team, change it there (and in `app.json` to keep them in sync). `--clean` prebuilds reset this, so redo it after one.
4. `npx expo run:ios --device` and choose the iPhone. This builds the development build, installs it, and starts Metro. The iPhone must be on the same Wi-Fi as the Mac to load the JavaScript bundle.
5. First launch only: if iOS says the developer is not trusted, go to Settings > General > VPN & Device Management, trust your developer certificate, and open the app again.
6. On the Capture tab, accept the camera prompt. There is no motion prompt.

Expected:

- The Capture tab fills with the live **back** camera image, upright, in portrait. Rotating the phone does not rotate the UI.
- The Sessions and Settings tabs open (Sessions shows "No sessions yet").
- No microphone prompt (and no Motion & Fitness prompt) appears, ever.
- Denied state: Settings app > CaptureKit > turn **Camera** off, return to the app (iOS may restart it). The Capture tab shows "Camera access is off" and an **Open Settings** button that opens CaptureKit's page in Settings. Turn Camera back on and the preview returns.
- Camera error: if the camera can't start (for example it is in use elsewhere), the Capture tab shows "The camera couldn't start" with the reason and **Try again**, never a silent black screen.
